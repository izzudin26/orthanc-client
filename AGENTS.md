# orthanc-client — Agent Instructions

## Project Overview

`orthanc-client` is a Node.js/TypeScript library that wraps the **Orthanc DICOM server REST API (v1.12.11)**. It is designed to be consumed from both TypeScript and JavaScript projects and published to npm.

## Tech Stack

| Tool | Purpose |
|---|---|
| **Bun** | Runtime, package manager, test runner |
| **TypeScript 5** | Primary language |
| **tsup** | Dual CJS + ESM build |
| **class-transformer** | Plain-object ↔ class mapping with decorators |
| **reflect-metadata** | Decorator metadata polyfill (required by class-transformer) |
| **@swc/core** | Transpiles `emitDecoratorMetadata` in the tsup build |

## Key Conventions

### Exports

Everything public **must** be re-exported from `src/index.ts`. Do not add new source files without updating the barrel.

### Models

- Models live in `src/models.ts`.
- Each model class uses `@Expose()` on every property (required by `excludeExtraneousValues: true`).
- Use `plainToInstance(Model, data, { excludeExtraneousValues: true })` to deserialize responses.

### Client Methods

- All HTTP methods go through the private `request<T>()` helper in `client.ts`.
- Binary responses (files, archives, frames) must use `getBinary()` / `binary: true`.
- Throw `OrthancError` on non-2xx responses — **never swallow errors**.
- Always cancel the AbortController timer after fetch resolves/rejects.

### Types

- Pure TypeScript interfaces (no class-transformer decorators) live in `src/types.ts`.
- Export all types so consumers can use them.

## Build & Test Commands

```bash
bun install          # install deps
bun run build        # compile to dist/ (CJS + ESM + .d.ts)
bun test             # run test suite
bun run lint         # type-check only (tsc --noEmit)
```

## Adding a New API Endpoint

1. Add request/response types to `src/types.ts` (if not already present).
2. If the response is a DICOM resource (Patient/Study/Series/Instance), add or update the model in `src/models.ts`.
3. Add the method to `OrthancClient` in `src/client.ts` under the appropriate section comment.
4. Re-export any new public types from `src/index.ts`.
5. Write at least one test in `tests/client.test.ts`.

## Orthanc API Reference

The full REST API specification is available via the `orthanc-api` skill. Key concepts:

- Resources are identified by Orthanc UUIDs (not DICOM UIDs).
- Hierarchy: `Patient → Study → Series → Instance`.
- Search is done via `POST /tools/find` with a `Level` and a `Query` map.
- Jobs are returned for async operations; use `waitForJob()` to poll completion.

## Publishing to npm

1. Set `name`, `version`, and `author` in `package.json`.
2. Run `bun run build` to produce `dist/`.
3. Run `bun publish` (or `npm publish`) — `prepublishOnly` triggers build automatically.
4. Ensure `files` in `package.json` only includes `dist/`.

## Security Notes

- Credentials are passed as Basic Auth headers — never log them.
- Do not accept arbitrary user-supplied URLs as base URL without validation at the call site.
- Avoid `eval` or `Function` constructors anywhere in the codebase.
